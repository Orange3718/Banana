# 개인 매매와 Atemoya 운영 경계

기준일: 2026-09-07 KST

## 결론

`Atemoya`는 회사 수익 운영 시스템이고, `upbit-auto-trader`는 사용자의 개인
매매 시스템이다. 두 영역은 같은 iMac에서 실행할 수 있지만, 계좌·키·주문·손익·
전략 상태·알림 대상을 공유하지 않는다.

현재는 같은 Git 저장소의 하위 폴더에 개인 매매 코드가 있으므로 운영 프로세스는
분리되어도 저장소 경계는 완전히 분리되지 않았다. 개인 매매를 장기 운영하려면
별도 private 저장소와 별도 비밀 파일로 옮긴다.

## 현재 실제 상태

| 영역 | 현재 상태 | 근거 |
| --- | --- | --- |
| Atemoya 회사 운영 | 8765, Docker/n8n/PostgreSQL/Ollama, 수익 콘텐츠 워크플로 | `scripts/preflight.sh` |
| 개인 대시보드 | 8766, 읽기 전용 API와 통합 화면 | `neural/api.py` |
| Upbit | 실제 워커 실행 중, 승인 없이 주요 4개 종목 자동운용 | `com.orange3718.upbit-auto-trader.upbit-worker` |
| Binance | 계좌 조회와 1시간봉 모의운용만 실행 중 | `neural/binance_futures.py`, `neural/paper.py` |
| 국내주식 | 연결하지 않음 | `stock=not_configured` |

Upbit와 Binance 상태를 한 화면에서 보지만, KRW와 USD를 임의로 합산하지 않는다.
회사 수익 지표에도 개인 거래의 잔고·수익·주문을 넣지 않는다.

## 공유할 것

- 개인 대시보드의 상태 표시 방식과 공통 운영 점검
- 서비스 생존 확인, 로그 형식, 백그라운드 재시작 방식
- 계좌별 조회 스키마와 이벤트 표시 규칙
- 성과 화면의 공통 지표 이름

## 분리할 것

- Upbit·Binance API 키와 회사용 자격증명
- 개인 매매용 데이터베이스와 Atemoya PostgreSQL 운영 데이터
- 개인 거래 Telegram 채널과 회사 알림 채널
- Upbit 전략·Binance 선물 전략·Atemoya 콘텐츠 전략
- 거래소별 주문 실행기, 포지션 원장, 손실 한도, 킬 스위치
- 개인 거래 수익과 Atemoya 제휴·광고·콘텐츠 수익
- 개인 매매 워커와 회사용 n8n/Publisher/Guardian

## 현재 흐름

```text
개인 거래소 API
  -> 거래소별 조회 수집기
  -> 개인 원장/모의운용
  -> 전략 신호
  -> 거래소별 위험 게이트
  -> 거래소별 주문 워커
  -> 체결 대조/손익 기록
  -> 개인 대시보드
```

```text
Atemoya 공개 자료·콘텐츠
  -> n8n/Ollama
  -> QA와 승인
  -> GitHub Pages 게시
  -> 유입·클릭·수익 측정
```

두 흐름은 회사 수익 데이터와 개인 매매 데이터를 서로 입력으로 사용하지 않는다.

## Binance 자동운용 전 필요한 구현

현재 Binance 모듈은 잔고·포지션 조회기다. 실주문 전환에는 다음이 필요하다.

1. Binance 전용 주문 실행기와 서명된 주문 요청
2. 계약별 가격·수량 단위와 최소 주문 검증
3. 단방향/헤지 모드와 레버리지 확인
4. 진입 직후 손절·익절 보호주문 등록
5. 주문 시간초과·부분체결·재시작 후 중복주문 방지
6. 마크가격·청산가격·펀딩비를 포함한 손익 계산
7. 실제 계좌 포지션과 내부 원장 대조
8. 계좌별 최대 증거금·최대 노출·일일 손실 한도
9. 24시간 모의운용 결과와 실거래 전환 시각 기록

24시간 모의운용은 운영 검증의 최소 구간일 뿐 수익을 보장하지 않는다. Binance
실주문 금액과 레버리지는 별도 설정으로 두며 Upbit 설정을 복사하지 않는다.

## 정리할 것

- 신규 개인 대시보드와 별도로 남아 있는 Streamlit/Windows 실행 경로를 legacy로
  표시하고 실수로 두 주문 워커가 동시에 실행되지 않게 한다.
- 개인 매매 코드와 회사 Atemoya 코드를 장기적으로 별도 private 저장소로 분리한다.
- `neural` 읽기 API의 주문 차단과 실제 Upbit 레거시 워커의 주문 경로를 화면에서
  명확히 구분한다.
- 오래된 인수인계 문서의 “주문 미구현·인증 전” 문구를 실제 현재 상태와 맞춘다.

## 개선 우선순위

1. Upbit 실거래 주문의 체결·수수료·손익을 별도 개인 원장에 기록한다.
2. Binance 펀딩비와 실수수료를 모의운용에 반영한다.
3. Binance 주문 실행기를 읽기 전용 모듈과 분리해 구현한다.
4. 두 거래소의 공통 위험 규칙과 거래소별 규칙을 각각 테스트한다.
5. 개인 매매 저장소·비밀 저장소·알림 채널을 Atemoya에서 분리한다.
6. 24시간 모의운용 이후에도 실제 주문은 낮은 노출과 1배 레버리지부터 시작한다.
