# 로컬 LLM 병렬 운영 설계

기준일: 2026-08-22

## 현재 측정값

- 장비: iMac21,1 / Apple M1 / 메모리 16GB
- 로컬 모델: Ollama qwen3.5:4b 약 3.2GB
- 짧은 한국어 작업 73토큰 응답: 약 10초, 약 7.3토큰/초의 전체 체감 속도
- 결론: 짧은 작업을 2개 병렬로 돌릴 수 있지만, 긴 생성 3개 이상은 메모리와 응답시간이 악화될 가능성이 높다.

## 로컬로 넘길 작업

### Lane A — 수집·정리

- RSS·HTML에서 제목·URL·날짜 추출
- 중복 URL 제거
- 상품명·가격·카테고리 정규화
- 한국어 문장 정리와 태그 생성

### Lane B — 콘텐츠 보조

- 제목 5개 후보 생성
- 첫 문장·FAQ·체크리스트 초안
- 네이버 블로그 초안 구조화
- Telegram 보고 문장 압축

### Lane C — 품질·운영

- 금지 표현 탐지: 치료·보장·허위 체험·과장
- 필수 고지문·링크·출처 누락 검사
- 후보별 근거 URL 매칭
- 사람이 검토할 문장만 추출

## 로컬에 넘기지 않을 작업

- 최종 수익성 판단과 사업 중단·확장 결정
- 의료·법률·금융처럼 근거 해석이 중요한 문장
- 검색 결과의 최신성 판단
- 공개 게시·가격·정산·계정 권한 변경

이 작업은 규칙 엔진 또는 사용자 승인, 필요할 때 외부 고성능 모델로 처리한다.

## 병렬 구조

수집 3개 → 정규화·중복 제거 → 후보 분류 / 제목·훅 생성 / 품질·고지 검사 → PostgreSQL 저장 → Telegram 요약 → 사람 검토 → 게시

## 동시성 기준

- 기본 동시 실행: 2개
- 각 호출 num_predict: 120~300
- 긴 650토큰 분석은 한 번에 하나만 실행
- 작업 사이에 결과를 DB에 저장해 중단 후 재개
- 실패 시 1회 재시도 후 외부 모델 또는 보류로 전환

## 예상 처리량

- 짧은 분류·제목 작업: 작업당 약 8~15초
- 2개 병렬 배치: 1분에 약 6~12개 짧은 작업
- 300토큰 초안: 약 30~60초
- 650토큰 시장 요약: 약 1~2분

실제 처리량은 입력 길이, Ollama 캐시, 동시 실행 수에 따라 달라지며 자동화 대시보드에서 duration_ms, eval_count를 기록한다.

## 1차 적용 순서

1. Commerce Scout의 자료 정리·중복 제거·제목 후보 생성을 로컬화
2. 네이버 초안 생성과 금지 표현 검사를 로컬화
3. Telegram 보고 압축을 로컬화
4. 7일 후 로컬 생성 콘텐츠의 조회·클릭을 외부 생성 콘텐츠와 비교

현금흐름에 직접 연결되는 제휴 링크·게시·성과 판단은 로컬 모델이 자동 확정하지 않는다.
