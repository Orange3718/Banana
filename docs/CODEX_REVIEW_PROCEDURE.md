# Codex 교차검토 절차 (온디맨드)

작성일: 2026-09-28

모든 변경마다 자동으로 돌리지 않는다. **아래 트리거 조건에 해당할 때만**
사람이 직접 실행한다. Claude가 짠 코드를 Codex가 독립적으로(가정을 물려받지
않고) 다시 검증하는 "maker-checker" 방식이다 — 만든 쪽이 스스로 채점하지
않는다.

## 1. 언제 요청하는가

**요청한다:**
- 실거래 리스크 로직 변경 — `strategy_router.py`, `neural/binance_live.py`,
  `risk_manager.py`, `kiwoom_client.py`의 주문 관련 부분, 손절·포지션 한도·
  일일 손실 한도에 영향을 주는 `config.py`/`.env.example` 필드
- 새 자동화(n8n 워크플로, LaunchAgent)를 **활성화**하기 직전
- 백테스트 결과를 근거로 실거래 설정을 바꿔 배포하기 직전
- Claude 스스로 판단에 자신이 없다고 명시한 경우

**요청하지 않는다:**
- 문서 수정, 읽기 전용 대시보드/API 추가, 테스트 추가
- 순수 리서치·백테스트 스크립트(아직 실거래에 반영 전)
- 이미 Codex가 한 번 검토해서 통과한 내용의 사소한 후속 수정

## 2. 사전 준비 (최초 1회만)

1. Codex CLI 설치: `npm install -g @openai/codex` (Node 22+ 필요 — 이
   Mac엔 이미 `~/.local`에 Node 24가 설치돼 있다).
2. `OPENAI_API_KEY`를 본인이 직접 설정한다 (계정/키라 Claude가 대신 할
   수 없다).
3. 별도 설정 불필요 — 저장소 루트의 `AGENTS.md`를 Codex가 자동으로 읽는다.

## 3. 실행 절차

1. Claude가 변경사항을 커밋하고 커밋 해시를 알려준다.
2. 터미널에서 저장소 루트로 이동해 Codex를 실행한다:

   ```bash
   cd /Users/orange/Developer/Banana-atemoya-ops
   codex exec "커밋 <해시>의 diff를 검토해줘. 이 코드는 Claude Code가 짰다.
   네가 처음부터 직접 검증한다고 생각하고 Claude의 가정을 그대로 믿지 마라.
   확인할 것: (1) 손절/포지션 한도/일일 손실 한도 로직이 의도대로 동작하는가,
   (2) 기존 동작을 깨뜨리는 부분이 있는가, (3) 이 저장소의 AGENTS.md와
   docs/TRADING_HANDOFF_2026-09-28.md 원칙과 어긋나는 부분이 있는가.
   문제 없으면 없다고 말하고, 있으면 구체적으로 어느 파일·줄이 왜 문제인지
   말해줘."
   ```

   (정확한 서브커맨드·플래그는 설치된 Codex CLI 버전에 따라 다를 수 있다 —
   `codex --help`로 먼저 확인한다.)
3. Codex의 결과를 그대로 Claude에게 붙여넣고 확인을 요청한다.
4. Claude가 지적사항을 반영하거나, 왜 문제가 아닌지 근거를 들어 설명한다.

## 4. 기록

매번 문서화하지 않는다(온디맨드 원칙과 어긋난다). **Codex가 실제로 뭔가를
잡아낸 경우에만** 해당 커밋 메시지나 그날의 핸드오프 문서에 한 줄 남긴다:
`Codex 교차검토로 발견: <내용>`.

## 왜 이렇게 하는가

- "Adversarial code review / maker-checker" — 코드를 만든 에이전트가
  스스로 채점하면 안 된다는 원칙. LLM이 자기 출력을 편애하는 경향이 연구로
  확인돼 있다.
- 매 커밋마다 돌리면 두 배의 시간·비용이 들면서 저위험 변경(문서, 테스트,
  읽기 전용 API)까지 검토하느라 정작 중요한 곳에 쓸 주의력이 흩어진다.
  그래서 실거래 리스크 로직처럼 실수 비용이 큰 곳에만 좁게 적용한다.
