# 02. MVP와 설계 결정

v1.0 · 관련 이슈 R03/R07/R08/R09/R12

## 1. 실험 정의

PROPOSED: `EXP-KR-LED-MASK-001` — 한국어 독자가 LED 마스크를 고를 때 광원·사용시간·A/S·반품 조건을 비교하도록 돕는다. 기존 후보 조사와 쿠팡파트너스의 국내 상품 범위를 결합한 가설이며 시장 검증·Owner 전략 확정이 아니다.

첫 공급자는 쿠팡파트너스로 고정한다. 판매 대상은 쿠팡파트너스가 허용한 국내 상품으로 한정하고, 의료 효능을 주장하지 않는다. 실제 상품·링크·정책·보고서 접근을 확인해야 한다.

첫 콘텐츠 3개 제안:

1. 저가 입문형·브랜드형·얼굴/목 확장형 비교: 가격보다 광원·사용시간·A/S를 중심으로 비교.
2. LED 마스크 구매 전 체크리스트: 의료 효능이 아니라 사용 조건·반품·보증을 확인.
3. 실제 사용 루틴과 주의사항: 과장된 전후 효과 없이 사용 편의성과 관리 방법 비교.

각 글은 동일 서비스 소개를 복제하지 않고 서로 다른 사용자 상황과 선택 질문을 다룬다. 실제 요금·운영시간·예약 상품은 공식 자료 확인 후 입력한다. 최종 상품과 링크가 미확정이면 초안 상태로 남긴다.

최대 5개 자산, 첫 언어 영어 한 개, 첫 목표 시장 한 개. 다국어·뷰티·IT 등 병행 출시는 제외한다. 이 결정은 첫 실험의 측정 가능성을 높이기 위한 제안이며 장기 카테고리 범위를 축소하지 않는다.

## 2. 가설과 성공 기준

| 가설 | 필요한 증거 | 반증·실패 처리 |
|---|---|---|
| 고객이 이동수단 선택에서 구체적인 어려움을 겪음 | 고객 질문·검색 의도·경쟁 페이지의 해결 공백 | 근거가 없으면 콘텐츠 양산 전 주제 재검토 |
| 상품이 고객의 예약·결제·이용 조건에 적합 | 공급자 상품 조건·지원 국가·사용일 | 부적합하면 해당 offer 제외 |
| 공급자가 성과·수수료를 돌려줌 | 실제 형식 보고·상태 정의 | 미제공 단위는 unavailable, 사용 가능한 단위로 실험 재설계 |
| 유지비 포함 공헌이익이 양수 | 성숙 순수수료·직접 비용·작업 시간 | 최소 증거 충족 후 UPDATE/중단 판단 |

주지표: 실험 귀속이 증명된 성숙 순수수료에서 직접 비용을 차감한 실험 공헌이익. 귀속이 프로그램까지만 가능하면 정확한 실험 이익을 보고하지 않는다.

보조 지표: Provider EPC, 유효 클릭, 검색 유입, Owner 시간, 보고 신선도, 미귀속 금액. 공급자 주문 단위와 클릭 단위가 맞지 않으면 CVR은 N/A.

확대 제안 조건 v1: 최소 2개의 성숙 보고 기간에서 반복 전환, 사전 정의한 표본 조건 충족, 양의 공헌이익, 월 예산·Owner 시간 목표 이내, 미해결 정책 문제 없음. 이는 운영 기본안이며 실제 보고 주기와 데이터로 보정한다. 확대의 규모·비용은 별도 결정을 기록한다.

## 3. 일정·예산·판정 계약

T0는 첫 공개 URL·측정 정상·보고 경로 검증이 모두 완료된 시점이다. D+7 기술 점검, D+30 초기 학습, D+90 포트폴리오 검토를 둔다. 실제 예약 이용·취소·지급 지연은 별도 maturity 시계로 관리한다.

설정 필수값:

| 설정 | 현재 값 | 의미 |
|---|---|---|
| monthly_cash_cap | 미정 | 월 사업 지출 상한 |
| experiment_cash_cap | 미정 | 첫 실험 지출 상한 |
| owner_minutes_target_week | 제안 60분, 미승인 | 자동 운영 목표이며 현재 실측 아님 |
| minimum_mature_clicks | 실제 전환 가정 확보 전 미정 | 299 같은 예시를 자동 규칙으로 사용하지 않음 |
| report_maturity_policy | 공급자 계약 대기 | booking/order/confirmed/cancel 가능 시점 |
| minimum_attribution_level | experiment_exact | 미달 시 글·실험별 손익 확정 금지 |

예산이 미정이면 유료 작업 dispatch는 거절한다. 이미 가진 로컬 자원으로 합성 데이터 설계·테스트는 진행 가능하다. 로컬 추론도 비용 0으로 기록하지 않고 사용량과 전력비 추정 여부를 구분한다.

실험 상태는 planned/running/paused/completed/cancelled로 기존 계약을 따른다. `WAIT_FOR_DATA`는 실험 상태가 아니라 결정 결과다. 데이터 품질 결과와 경영 결정 결과를 한 status에 섞지 않는다.

## 4. ADR — 기술 기본 결정

| ADR | 결정 | 이유와 대안 | 상태 |
|---|---|---|---|
| A01 | 신규 `affiliate` schema, public 핵심 ID 참조 | 같은 이름 덮어쓰기 방지. 별도 DB는 초기에 운영 복잡성 증가 | DESIGN |
| A02 | 수수료 원장 단일 소유, public.revenue 복사 없음 | status와 음수 제약 불일치·중복 합산 방지 | DESIGN |
| A03 | 첫 parser는 파일 업로드 기반 | API 자격과 별개로 보고·대사 검증 가능. 자동 API는 후속 | DESIGN |
| A04 | 불변 콘텐츠 revision·승인 binding | 승인 뒤 변경·오래된 배포 성공 오판 방지 | DESIGN |
| A05 | 새 상업 승인은 public.approvals, 신규 publisher queue | 기존 approval_requests 기반 publisher와 분리 | DESIGN |
| A06 | 정적 사이트 + 독립 collector + iMac pull | iMac 장애가 사이트·구매 경로에 전파되지 않음 | DESIGN |
| A07 | Cloudflare Workers Static Assets + Worker/D1 후보 | 정적 자산·API·버퍼 조합 가능. 계정/계약/비용 미확인 | PROPOSED |
| A08 | 직접 제휴 링크, 비동기 클릭 | provider 파라미터 보존, 수집 장애와 구매 이동 분리 | DESIGN |
| A09 | 원본 보고는 private 파일 저장소, manifest만 Git | 자료·개인정보 공개 방지. 운영 백업 경로 별도 확정 | DESIGN |
| A10 | 초기 SQL jobs + DB lease | 새 큐 제품 추가 없이 명시적 실패 복구 | DESIGN |

DESIGN은 상세 설계의 기준으로 채택했다는 뜻이다. 운영 환경에 이미 적용했거나 지출을 승인받았다는 뜻은 아니다.

## 5. Owner·외부 증거가 필요한 결정

| ID | 결정할 내용 | 준비된 기본안 | 결정이 필요한 시점 |
|---|---|---|---|
| D01 | 첫 시장·고객·카테고리 | 미국 거주 영어 독자의 서울 입국 이동 | 실제 콘텐츠 조사 범위 확정 전 |
| D02 | 계정 사용 가능한 첫 공급자 | Coupang Partners, 로그인·리포트 메뉴 확인, API 키는 승인 대기 | 실데이터 adapter 승인 전 |
| D03 | 운영 호스팅·도메인·이전 | Cloudflare 후보, GitHub는 소스 유지 | 운영 계정 설정·배포 전 |
| D04 | 월/실험 예산, 운영 책임 | 신규 유료 사용 0 허용, 시간 목표 제안 | 유료 작업 활성화 전 |
| D06 | 게시 권한 | 최초 파일럿 개별 revision 승인 | 공개 게시 전 |
| D07 | 데이터 처리·보존·동의 조건 | 최소 이벤트·원시 30일 제안 | 공개 수집 전 |

D05(데이터 소유권)는 A01/A02/A04/A05로 상세 설계상 해결했다. 운영 호환성 테스트는 아직 필요하다. D01–D07을 미결이라는 이유로 기술 명세 작성까지 멈출 필요는 없다.

## 6. 검증 근거와 범위

쿠팡파트너스 포털에서 로그인·리포트·링크 생성 메뉴를 확인했지만 현재 수익 요약은 0이며 API 키 발급은 비활성화다. 기존 LED 마스크 후보 조사와 포털의 국내 상품 범위를 바탕으로 MVP를 재정렬한 추론이며, 실제 전환·수수료·지원 필드는 아직 입증하지 않았다. [공급자 조사](03-provider-contract.md).
