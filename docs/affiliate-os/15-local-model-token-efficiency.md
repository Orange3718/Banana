# 15. 로컬 모델·토큰 효율 운영 기준

갱신: 2026-09-13 KST. 목적은 비용과 지연을 줄이면서도 근거 없는 제휴 콘텐츠가 게시되지 않도록 모델 역할을 분리하는 것이다.

## 실제 기준선

최근 `local_llm_runs` 집계에서 `ollama-local / qwen3.5:4b`는 440회 실행, 435회 완료, 5회 오류였다. 평균 실행시간은 약 16.8초다. 작업별 평균 출력은 SNS 성공 요약 230자(131회), 제목 변형 188자(131회), 트렌드 평가 1,014자(113회), 신규 수익 콘텐츠 후보 847자(65회)였다. 이 수치는 모델 품질의 보증이 아니라 현재 운영 비용·지연의 관측값이다.

## 결정한 라우팅

| 작업 | 기본 모델 | 제한 | 이유 |
|---|---|---|---|
| 제목 변형·짧은 요약·분류 | 로컬 Qwen | 짧은 출력, 원문 근거만 | 반복 작업의 비용·지연 절감 |
| 트렌드 평가·콘텐츠 후보 | 로컬 Qwen 우선 | 입력 근거와 필수 필드 고정 | 민감 자료 외부 전송 방지, 재현성 |
| 현재 DailyTrend 1차 분석 | Gemini 유지 | `maxOutputTokens` 4096→1400 | 기존 운영 경로의 회귀를 막고 과다 출력을 제한 |
| DailyTrend 장애 시 fallback | 로컬 Qwen | 900 토큰 상한 | 장애 시에도 bounded response 보장 |

Gemini를 전부 제거했다고 가정하지 않는다. 실제 실행 기록과 workflow 설정을 분리해 표시하며, 라우팅 변경은 동일 입력 fixture와 비용·품질 비교 후에만 한다.

## 토큰·품질 가드레일

1. 시스템 프롬프트에 출력 형식·최대 길이·근거 필드를 명시한다.
2. 빈 응답, JSON 파손, 근거 없는 숫자, 링크가 없는 제휴 후보는 게시 큐로 보내지 않고 격리한다.
3. 재시도는 같은 입력의 idempotency key를 사용하고, 무제한 재시도나 조용한 모델 전환을 금지한다.
4. 프롬프트·모델·토큰 상한·입력 해시·출력 크기·지연·오류를 실행 기록에 남긴다.
5. 원본 보고서와 개인정보·API 키는 로컬 처리 경계를 넘기지 않는다.

## 개선 전후

| 항목 | 이전 | 개선 후 | 근거 |
|---|---|---|---|
| DailyTrend Gemini 상한 | 4096 | 1400 | 과다 출력 방지, export 수정 및 검사 |
| fallback 코드 | 실제 줄바꿈이 JS 단일 문자열에 포함될 위험 | 이스케이프된 `\\n` | n8n Code 노드 SyntaxError 재발 방지 |
| 모델 선택 설명 | 작업별 근거가 흩어짐 | 관측 집계와 라우팅 표로 통합 | `local_llm_runs` 440회 집계 |
| 성공 판정 | 모델 응답 존재 여부 중심 | 형식·근거·링크·재시도까지 검증 | 게시 안전성 기준 |

## 검증 및 다음 측정

현재는 export 정적 검사와 기존 workflow 테스트까지다. 실제 스케줄 실행 후에는 작업별 p50/p95 지연, 입력·출력 토큰, 오류율, 재시도율, 게시 후 클릭·수익 연결을 비교한다. 측정값이 없으면 비용 절감이나 전환 개선을 주장하지 않는다.
