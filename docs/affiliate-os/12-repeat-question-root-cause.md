# 12. 왜 같은 질문을 반복하게 했는가

2026-09-13 · 원인 분석·개선 전후·재발 방지 기록

## 결론

사용자가 설명을 충분히 하지 않아서가 아니다. 담당 AI가 최신 지시와 실행 상태를 일관되게 유지하지 못하고, 부분 구현을 전체 완료처럼 보고했으며, 다음 행동 대신 안내로 끝냈다. 그 결과 사용자가 기억 저장소·일정 진행자·결과 검증자 역할을 떠맡았다.

## 문서 외 실제 개선

1. 클릭 이벤트를 내부 이동·일반 외부 이동·쿠팡 제휴 이동으로 분리했다. 링크 이동을 가로막지 않고, 오른쪽 클릭과 이중 초기화의 중복을 억제한다. 추적키가 없으면 임의 상품에 귀속하지 않고 unmapped로 남긴다.
2. 배포가 저장소 전체를 올리던 설정을 공개 파일 목록 기반 dist-public로 변경했다. 운영 문서·SQL·내부 대시보드는 공개 산출물에 들어가지 않는다. 이것은 기존 Git 저장소에서 파일을 삭제하거나 공개 Git 이력을 비공개로 만드는 조치가 아니다.
3. 사이트 검사를 공개 대상에 한정하고, 최종 산출물에는 허용 목록 외 파일이 하나라도 있으면 실패하도록 했다. Upbit 의존성 HTML 때문에 수백 개의 무관한 오류가 나던 범위 문제도 해소한다.
4. daily-use 페이지의 쿠팡 수수료 고지 누락과 기존 식초 페이지 추적키 누락을 보완했다. 과거 ‘두 페이지 고지 확인 완료’ 보고는 정확하지 않았다.
5. 배포 흐름에 클릭 8개·산출물 경계 3개 자동 검사를 넣었다. QA를 ‘더 꼼꼼히 하겠다’는 약속으로만 남기지 않았다.
6. 기존 쿠팡 포털에서 실제 보고서를 다운로드했다. 헤더만 있는 파일을 0원으로 전기하지 않고, 원본 해시 보존·중복 헤더 표시·수입 전 검사 5개를 추가했다([13번 기록](13-coupang-report-inspection.md)).
7. 포털의 현재 고지 원문은 ‘수수료를 제공받습니다’였다. 첫 보완에서 기존 사이트 문구를 그대로 재사용한 한계를 발견해 원문으로 다시 맞추고 공개 배포를 확인했다. 익숙한 문구를 현재 제공자 요구사항 확인의 대체물로 쓰지 않는다.

## 반추: 아직 인지하지 못하기 쉬운 부분

- 지시를 저장하는 것과 다음 실행에서 실제 읽게 만드는 것은 다르다. 그래서 상세 MD 추가만 하지 않고 시작 지점과 preflight에 연결했다.
- 계정이 로그인되어 있어도 그 계정의 측정 ID·속성·리포트 수신은 각각 확인해야 한다. 반대로 수신 미검증이라고 새 로그인부터 요청하는 것도 잘못이다.
- 웹사이트에 링크를 붙이는 것, 방문자를 확보하는 것, 제휴 수익이 발생하는 것은 서로 다른 성과다. 현재 첫 번째만 있다고 수익구조가 검증된 것은 아니다.
- 수정 전 클릭과 v2 클릭은 정의가 달라 그대로 비교하면 안 된다. v2를 별도 구간으로 보고 과거 숫자를 재구성할 근거가 없으면 보정치를 지어내지 않는다.
- 비용/귀속 조회에 복수 행이 붙으면 단일 사례에서 통과한 합계가 실제 데이터에서 배수로 불어날 수 있다. 복수 귀속·복수 비용·혼합 통화 반례가 다음 DB 검증 우선순위다.
- ‘다음부터 반복하지 않겠다’는 개선 효과도 아직 장기 검증한 사실이 아니다. 다음 작업에서 동일 질문 재발 여부와 사용자 개입 원인을 기록해 효과를 검증해야 한다.

## 효과 확인 기준

- 이미 기록된 정보·승인을 다시 요구한 횟수와 발생 이유를 기록한다. 이번 변경만으로 반복률 0%를 주장하지 않는다.
- 게시 성공은 Git push가 아닌 배포 완료와 공개 본문으로 확인한다.
- 숫자는 source/time window/수집 상태가 있을 때만 성과로 보고한다. 미확인 값은 0이 아닌 UNKNOWN으로 유지한다.
- 사용자에게 일을 넘기기 전에 기존 기록·로그인 세션·대체 경로 확인 결과를 남긴다.
