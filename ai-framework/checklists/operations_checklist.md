# Operations Readiness Checklist

## 소유권과 서비스 수준

- [ ] 서비스 소유자, 온콜, 의존 서비스 연락처가 있다.
- [ ] 사용자 관점 SLI/SLO와 오류 예산이 정의되어 있다.
- [ ] 지원 시간, 응답 목표, 에스컬레이션 경로가 명확하다.
- [ ] 반복 수동 작업에 소유자와 자동화 우선순위가 있다.

## 관찰 가능성

- [ ] 핵심 여정의 성공률·지연·정확성을 측정한다.
- [ ] 큐 정체, 중복, 재시도, DLQ, 스케줄 누락을 감시한다.
- [ ] 로그에 상관관계 ID와 필요한 상태 전환이 있다.
- [ ] 경보는 사용자 영향과 연결되고 실행 가능한 런북을 가진다.
- [ ] 같은 사건의 알림 폭주를 억제하고 복구도 알린다.

## 실패와 복구

- [ ] 의존성 중단·지연·부분 응답 시 동작을 시험했다.
- [ ] 안전 중지, 격리, 재개, 재처리 절차가 있다.
- [ ] timeout, retry, backoff, idempotency 정책이 일관된다.
- [ ] 백업 복원이 RTO/RPO 안에 가능한지 시험했다.
- [ ] 데이터 정합성 검사와 보상 절차가 있다.

## 용량과 비용

- [ ] 피크 부하, 성장률, 저장 증가량을 추정했다.
- [ ] 자동 확장과 하드 한도가 위험에 맞게 설정되었다.
- [ ] API, 모델, GPU, 전송, 저장 비용을 관찰한다.
- [ ] 예산 초과 경보와 자동 비용 상한이 있다.
- [ ] 공급자 할당량·요금·정책 변화의 대체 경로가 있다.

## 변경 관리

- [ ] 모든 운영 변경이 버전·승인·감사 가능하다.
- [ ] 인증서·키·의존성 만료 전에 경보한다.
- [ ] 런북과 대시보드를 변경과 함께 갱신한다.
- [ ] 정기 복구·장애·보안 훈련을 예약하고 결과를 기록한다.
- [ ] 회고의 조치에 소유자, 기한, 완료 증거가 있다.
