# MVP Readiness Checklist

MVP는 기능 축소판이 아니라 가장 위험한 가정을 최소 비용으로 검증하는 실험이다. 해당 없음은 사유를 기록한다.

## 문제와 실험

- [ ] 초기 고객 세그먼트, 사용자, 구매자가 구분되어 있다.
- [ ] 문제의 빈도·강도·현재 해결 행동에 직접 증거가 있다.
- [ ] 가장 위험한 가정 1~3개가 명시되어 있다.
- [ ] MVP가 각 가정을 반증할 수 있다.
- [ ] 성공·실패·중단 기준과 측정 기간이 정해져 있다.
- [ ] MVP 없이 더 싸게 검증할 방법을 검토했다.

## 범위와 경험

- [ ] 핵심 사용자 여정 하나가 처음부터 끝까지 동작한다.
- [ ] 비범위와 수동 운영 구간이 명시되어 있다.
- [ ] 오류·빈 상태·대기·취소·지원 경로가 있다.
- [ ] 접근 권한과 데이터 수집 동의가 사용자에게 명확하다.
- [ ] 가치 전달 전 불필요한 가입·입력 단계를 제거했다.

## 기술과 데이터

- [ ] 시스템 오브 레코드와 데이터 소유자가 정해져 있다.
- [ ] 입력 검증, 권한 검사, 비밀 관리가 구현되어 있다.
- [ ] 중복 실행과 부분 실패가 데이터 손상을 만들지 않는다.
- [ ] 최소 로그·지표로 핵심 여정과 실패를 추적할 수 있다.
- [ ] 백업 또는 안전한 원본 보존 방식이 있다.
- [ ] 프로덕션 데이터로 되돌릴 수 없는 실험을 하지 않는다.

## AI 기능(해당 시)

- [ ] 비-AI 기준선과 AI 사용 이유가 있다.
- [ ] 대표 평가 사례와 합격 임계값이 있다.
- [ ] 고위험 출력은 결정론적 검사 또는 사람 승인을 거친다.
- [ ] 모델의 권한·반복·토큰·비용 상한이 있다.
- [ ] 근거가 없거나 불확실한 경우 거부·에스컬레이션한다.

## 사업과 비용

- [ ] 가격 또는 지불 의사 검증 계획이 있다.
- [ ] 고객·요청 단위의 변동비 상한이 있다.
- [ ] 실험 최대 손실과 추가 지출 승인자가 정해져 있다.
- [ ] 개인정보·규정·계약상 최소 의무를 확인했다.

## MVP 종료 판정

- [ ] 결과가 가설과 연결되어 해석 가능하다.
- [ ] 계속 / 수정 / 중단 기준 중 하나로 결정한다.
- [ ] 학습과 반증된 가정을 기록한다.
- [ ] 다음 단계에 필요한 증거와 책임자를 정한다.
