# Release Checklist

## 제품과 결정

- [ ] 출시 범위, 비범위, 대상 사용자, 성공 지표가 승인되었다.
- [ ] P0/P1 리뷰 이슈가 해결되거나 명시적 책임자가 위험을 수용했다.
- [ ] 법률·보안·개인정보·마케팅 고지가 검토되었다.
- [ ] 지원, 운영, 사고 대응 소유자가 준비되어 있다.
- [ ] 출시 중단 기준과 결정권자가 명확하다.

## 코드와 데이터

- [ ] 변경 diff가 리뷰되고 요구사항과 추적된다.
- [ ] 단위·통합·계약·보안·회귀 테스트가 통과했다.
- [ ] API와 스키마의 하위 호환성을 확인했다.
- [ ] 마이그레이션이 재실행 가능하며 실제 규모로 리허설되었다.
- [ ] 백업과 복원 검증이 완료되었다.
- [ ] 비밀, 디버그 설정, 테스트 계정·데이터가 산출물에 없다.

## 배포

- [ ] 재현 가능한 빌드와 고정된 아티팩트를 사용한다.
- [ ] 환경 설정과 의존 서비스 준비 상태를 확인했다.
- [ ] canary / 점진 노출 / feature flag 전략이 위험에 맞는다.
- [ ] 배포 단계마다 관찰·중단·롤백 조건이 있다.
- [ ] 롤백이 스키마·데이터 변경과 호환된다.
- [ ] 배포 명령, 권한, 예상 시간이 런북과 일치한다.

## 관찰과 운영

- [ ] 핵심 사용자 여정의 synthetic 또는 실사용 검증이 있다.
- [ ] 가용성, 지연, 오류, 정확성, 비용 지표가 표시된다.
- [ ] 경보가 올바른 담당자에게 테스트 전송되었다.
- [ ] 로그·메트릭·트레이스로 요청을 끝까지 추적할 수 있다.
- [ ] 용량, 할당량, 인증서, 디스크, 공급자 한도를 확인했다.
- [ ] 온콜과 고객 커뮤니케이션 경로가 준비되어 있다.

## 출시 후

- [ ] 배포 직후 smoke test의 증거를 저장한다.
- [ ] 정해진 관찰 기간 동안 성공·오류·비용을 비교한다.
- [ ] 예상 밖 지표를 정상으로 임의 해석하지 않는다.
- [ ] 사고와 사용자 피드백을 위험 등록부에 반영한다.
- [ ] 종료 기준 충족 후 출시 상태와 잔여 위험을 기록한다.
