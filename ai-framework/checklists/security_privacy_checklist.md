# Security and Privacy Checklist

## 자산과 경계

- [ ] 자산, 사용자 유형, 외부 시스템, 신뢰 경계가 문서화되어 있다.
- [ ] 데이터가 공개 / 내부 / 기밀 / 개인정보로 분류되어 있다.
- [ ] 위협 모델에 악의적 사용자, 침해된 계정, 공급자 장애가 포함되어 있다.
- [ ] 외부 입력과 AI 생성 출력을 비신뢰 데이터로 취급한다.

## 인증과 권한

- [ ] 민감 작업은 서버 측에서 인증과 권한을 확인한다.
- [ ] 객체·테넌트 수준의 접근 통제가 테스트되었다.
- [ ] 서비스 계정과 사람 계정의 권한이 분리되어 있다.
- [ ] 관리자·게시·결제·삭제 권한은 최소화되고 만료 가능하다.
- [ ] 고위험 행동에 재인증 또는 승인 게이트가 있다.

## 데이터와 개인정보

- [ ] 필요한 데이터만 명확한 목적으로 수집한다.
- [ ] 동의, 열람, 수정, 삭제, 보존 절차가 정의되어 있다.
- [ ] 전송·저장 암호화와 키 소유·회전 정책이 있다.
- [ ] 로그·백업·분석 사본에 민감정보 보호가 적용된다.
- [ ] 운영·테스트 데이터의 분리와 마스킹이 확인되었다.

## 입력·출력·실행

- [ ] 쿼리, 명령, 경로, URL, 파일, 템플릿 입력을 경계에서 검증한다.
- [ ] 출력은 HTML, SQL, 셸 등 사용 컨텍스트에 맞게 처리한다.
- [ ] SSRF, injection, traversal, replay, resource exhaustion을 시험했다.
- [ ] 업로드 파일의 형식·크기·저장 위치·악성 콘텐츠를 통제한다.
- [ ] 에이전트 도구는 허용 목록, 샌드박스, 비용·반복 상한을 가진다.

## 비밀과 공급망

- [ ] 비밀이 저장소, 로그, 프롬프트, 이미지에 존재하지 않는다.
- [ ] 환경별 비밀과 최소 권한 키를 사용한다.
- [ ] 비밀 유출 시 폐기·회전 절차와 책임자가 있다.
- [ ] 의존성 버전과 출처가 고정되고 취약점 검사가 실행된다.
- [ ] 빌드·배포 산출물의 출처와 무결성을 확인할 수 있다.

## 탐지와 대응

- [ ] 인증·권한·관리자·민감 데이터 접근이 감사된다.
- [ ] 경보에는 소유자, 심각도, 런북, 에스컬레이션이 있다.
- [ ] 침해 계정과 키를 신속히 격리할 수 있다.
- [ ] 증거 보존, 통지, 복구, 회고 절차가 있다.
- [ ] 백업 복원과 사고 대응 훈련 결과가 기록되어 있다.
