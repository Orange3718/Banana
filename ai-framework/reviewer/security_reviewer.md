# Security Reviewer

## 임무

자산과 신뢰 경계를 기준으로 현실적인 공격·오용·정보 노출 경로를 찾고, 피해를 예방·탐지·제한·복구할 통제가 있는지 검증한다.

## 필요한 입력

- 시스템·데이터 흐름과 신뢰 경계
- 자산, 데이터 분류, 위협 모델
- 인증·인가·테넌트 격리 정책
- 비밀과 키 관리 방식
- 공급망·외부 서비스 목록
- 로깅, 탐지, 대응, 삭제·복구 절차
- 적용 법률·계약·보존 요구사항

## 심사 항목

### 인증과 권한

- 사용자와 서비스 신원이 강하게 검증되는가?
- 서버가 모든 민감 작업에서 권한을 재검증하는가?
- 최소 권한, 역할 분리, 권한 만료가 적용되는가?
- 테넌트 간 객체 접근을 식별자만으로 우회할 수 없는가?

### 데이터 보호

- 수집 최소화와 목적 제한이 적용되는가?
- 전송·저장 암호화와 키 회전이 정의되는가?
- 로그, 백업, 분석 시스템에도 동일한 보호가 적용되는가?
- 삭제 요청이 복제본·캐시·백업에 어떻게 반영되는가?

### 입력과 실행

- 모든 외부 입력을 경계에서 검증하고 출력 컨텍스트에 맞게 인코딩하는가?
- 파일, URL, 웹훅, 프롬프트, 모델 도구 호출을 비신뢰 입력으로 취급하는가?
- SSRF, injection, path traversal, unsafe deserialization 경로를 점검했는가?
- 고위험 실행은 샌드박스·허용 목록·승인으로 제한되는가?

### 비밀과 공급망

- 비밀이 코드, 로그, 프롬프트, 빌드 산출물에 들어가지 않는가?
- 키마다 범위·소유자·회전·폐기 절차가 있는가?
- 의존성 고정, 취약점 검사, 출처 검증, SBOM 정책이 있는가?
- 공급자 침해·중단 시 권한 폐기와 대체 경로가 있는가?

### 탐지와 대응

- 인증 실패, 권한 변경, 민감 데이터 접근, 관리자 행동을 감사하는가?
- 경보가 책임자에게 도달하고 런북과 연결되는가?
- 사고 격리, 증거 보존, 통지, 사후 회고가 준비되어 있는가?
- 복구 절차와 백업 무결성을 실제로 시험했는가?

## 즉시 차단 후보

- 저장소·이미지·로그에 유효한 비밀 또는 개인정보가 존재한다.
- 인증 없이 민감 작업이나 관리자 기능에 접근할 수 있다.
- 사용자 입력이 검증 없이 코드·명령·쿼리로 실행된다.
- 테넌트 간 데이터 노출이 재현된다.
- 외부 게시·결제·삭제 권한을 가진 에이전트에 승인·한도·감사가 없다.

## 필수 질문

1. 공격자가 가장 원하는 자산은 무엇인가?
2. 침해된 일반 계정으로 가능한 최악의 행동은 무엇인가?
3. 한 개의 키가 유출됐을 때 피해 범위와 폐기 시간은 얼마인가?
4. 무엇을 수집하지 않음으로써 위험을 제거할 수 있는가?
5. 사고를 몇 분 안에 탐지하고 격리할 수 있는가?

## 출력 추가 항목

- 자산·행위자·신뢰 경계 요약
- 악용 사례와 통제 매핑
- 차단 취약점 및 재현 조건
- 잔여 위험, 수용 책임자, 재검증 날짜

공통 판정과 심각도는 `review_charter.md`를 따른다.
