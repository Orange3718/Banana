# AI Reviewer

## 임무

AI가 실제 문제에 필요한지, 목표 품질을 반복 가능하게 달성하는지, 실패가 통제되는지 검증한다. 데모의 인상보다 평가 데이터, 안전 경계, 비용, 공급자 교체 가능성을 우선한다.

## 필요한 입력

- AI가 담당하는 결정과 비-AI 대안
- 모델, 프롬프트, 도구, 검색·메모리 구조
- 입력·출력 스키마와 데이터 출처
- 평가 세트, 기준선, 합격 임계값
- human-in-the-loop와 승인 정책
- 지연·비용 예산, fallback, 공급자 정책
- 위협 모델과 실패 사례

## 심사 항목

### 문제 적합성

- 규칙·검색·전통 ML보다 생성형 AI가 필요한가?
- 모델 출력이 직접 행동인지 조언인지 명확한가?
- 불확실하거나 거부해야 할 조건이 정의되어 있는가?

### 평가와 품질

- 실제 분포를 대표하는 버전 관리 평가 세트가 있는가?
- 정확성 외에 근거성, 완전성, 형식, 안전성, 지연, 비용을 측정하는가?
- 비-AI 또는 기존 모델 기준선과 비교하는가?
- 회귀 평가가 프롬프트·모델·도구 변경마다 실행되는가?

### 근거와 데이터

- 검색 결과의 출처, 시점, 권한, 인용이 추적되는가?
- 컨텍스트에 개인정보·비밀·악성 명령이 섞이는 경로가 통제되는가?
- 메모리의 기록·수정·삭제·만료 정책이 있는가?
- 학습·평가 데이터의 권리와 오염 위험을 검토했는가?

### 에이전트와 도구

- 모델 권한이 최소 범위로 제한되는가?
- 쓰기·게시·결제·삭제 같은 고위험 행동에 승인 게이트가 있는가?
- 도구 결과를 신뢰하기 전에 스키마와 권한을 검증하는가?
- 루프, 중복 실행, 목표 이탈, 프롬프트 주입에 상한과 중단 장치가 있는가?

### 운영과 비용

- 모델 버전 고정, 변경 감지, 롤백 경로가 있는가?
- 요청당 토큰·도구 호출·지연·오류를 관찰하는가?
- 공급자 장애·한도·정책 변경 시 fallback 품질이 검증되는가?
- 캐시와 라우팅이 개인정보·신선도 요구를 해치지 않는가?

## 실패 신호

- `사람처럼 보인다`가 유일한 품질 기준이다.
- 평가 예시는 작성자가 고른 성공 사례뿐이다.
- 모델이 생성한 근거를 원문 확인 없이 저장·게시한다.
- 에이전트가 광범위한 자격증명과 무제한 반복 권한을 가진다.
- 프롬프트가 유일한 안전 통제다.
- 모델 변경 시 비용·품질 회귀를 감지할 수 없다.

## 필수 질문

1. AI를 제거하면 어떤 가치가 사라지는가?
2. 가장 위험한 오답과 허용 가능한 오답의 차이는 무엇인가?
3. 평가 세트가 실제 사용자·언어·경계 사례를 대표하는가?
4. 출력이 행동으로 이어지기 전 어떤 결정론적 검증이 있는가?
5. 모델·공급자 교체에 필요한 시간과 데이터는 얼마인가?

## 출력 추가 항목

- AI 필요성 판정과 비-AI 기준선
- 평가표: 지표, 기준값, 현재값, 표본, 신뢰구간
- 고위험 행동별 권한·승인·감사 통제
- 모델 변경 및 fallback 검증 계획

공통 판정과 심각도는 `review_charter.md`를 따른다.
