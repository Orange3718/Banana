# Neural Trade 사용자 가이드

## 1. 현재 가능한 일

이 대시보드는 Upbit 현물과 Binance USD-M 선물 계좌를 분리해 조회하고, 전략 후보와 과거 기록을 분석하기 위한 도구입니다. 신규 주문 실행기는 연결되어 있지 않습니다. 화면의 `주문 실행 미연결` 표시는 오류가 아니라 안전 상태입니다.

인증 없이 사용할 수 있는 기능은 다음과 같습니다.

- 사이버펑크 대시보드와 운영 연결망 확인
- 전략 연구실에서 세 가지 전략 조건과 위험 확인
- 합성 캔들 기반 기능 검증 결과 비교
- 기존 판단·거래 이력 조회
- 종목 그룹과 전략·알림 설정 초안 저장
- Mac 이전용 백업·복원과 공개 API 사전점검

## 2. 시작과 종료

Windows에서는 `start_neural_dashboard.bat`을 더블클릭합니다. 종료할 때는 `stop_neural_dashboard.bat`을 사용합니다. 대시보드 주소는 `http://127.0.0.1:8765`입니다.

Mac에서는 다음 명령을 사용합니다.

```bash
bash tools/setup_macos.sh
bash tools/start_neural.sh
bash tools/stop_neural.sh
```

## 3. 왼쪽 메뉴

| 메뉴 | 의미 | 사용 방법 |
| --- | --- | --- |
| 통합 운영 | 거래소와 보유자산의 연결 관계 | 노드를 눌러 상태와 근거를 확인합니다. 통화가 다른 자산은 환율 없이 합산하지 않습니다. |
| Upbit 현물 | KRW 잔고와 모든 보유 코인 | 현재가·평가액·미실현손익을 확인합니다. |
| 국내주식 | 향후 증권사 연결 영역 | 현재는 연결 대기 상태입니다. |
| Binance 선물 | USD-M 잔고와 포지션 | 인증 전에는 `비활성`, 인증 후에는 방향·레버리지·손익을 표시합니다. |
| 판단·거래 이력 | 추천·주문 요청·체결 등 원장 | 이벤트 이름과 사유를 구분해 봅니다. 주문 요청을 체결로 간주하지 않습니다. |
| 전략 연구실 | 오프라인 전략 비교 | 거래 수, 승률, 순수익, 최대낙폭, 손익비를 함께 봅니다. |
| 종목·그룹 | 감시할 종목 묶음의 초안 | 체크박스로 고른 뒤 그룹 이름을 입력하고 초안을 저장합니다. 아직 실거래에 적용되지 않습니다. |
| 전략 설정 | 금액·주기·레버리지 초안 | 값을 수정해 저장해도 즉시 거래되지 않습니다. |
| 알림 설계 | Telegram 알림 순서와 주기 초안 | 위험 알림을 가장 위에 두는 것을 권장합니다. |
| 사용법·용어 | 화면 용어의 쉬운 설명 | 항목을 눌러 펼치고 닫습니다. |

## 4. 전략 연구실 읽는 법

`거래 수`가 너무 적으면 승률을 신뢰하지 않습니다. `승률`이 높더라도 평균 손실이 크면 나쁜 전략일 수 있습니다. `순수익`은 수수료와 슬리피지를 뺀 결과를 사용합니다. `최대낙폭`은 최고 자산에서 얼마나 크게 감소했는지 나타냅니다. `손익비(Profit Factor)`는 총이익을 총손실로 나눈 값이며 거래 수와 최대낙폭을 함께 확인해야 합니다.

현재 표시되는 데이터는 합성 캔들이므로 전략 코드가 정상적으로 작동하는지만 보여줍니다. 실제 성과 판단에는 사용하지 않습니다.

### Donchian 추세 돌파

최근 20개 봉의 최고가를 거래량과 함께 돌파할 때 진입하고 최근 10개 봉 최저가를 이탈하면 청산합니다. 강한 추세에 유리하고 횡보장에 불리합니다.

### Dual Thrust 변동성 돌파

이전 가격 범위로 상단선과 하단선을 계산합니다. 상단 돌파를 추세 시작 후보로 보고 하단 이탈을 실패로 봅니다. 급등 추격을 막는 필터가 필요합니다.

### RSI2·볼린저 평균회귀

장기 추세가 무너지지 않은 상태에서 단기 과매도와 볼린저 하단 접근이 함께 나타날 때 반등을 관찰합니다. 지속적인 하락장에서는 사용하지 않습니다.

## 5. 화면 색상

- 청록색: 정상 조회, 선택 상태, 양호한 값
- 녹색: 보유자산 또는 양수 손익
- 노란색: 지연, 미확인, 주의가 필요한 상태
- 분홍·빨간색: 손실 또는 주요 위험
- 회색: 연결 전, 데이터 없음, 적용되지 않은 초안

## 6. 인증 전 확인

```bash
.venv-next/bin/python -m neural.preflight
```

`public_apis` 세 항목이 모두 `ok: true`이면 공개 네트워크 연결은 정상입니다. `credentials`는 키의 존재 여부만 표시하고 실제 키를 출력하지 않습니다.

## 7. 인증 후 검증 순서

1. 실행 장비의 공인 IP를 거래소에 등록합니다.
2. 출금 권한 없이 조회 권한만 부여합니다.
3. `.env`에 키를 직접 입력합니다.
4. 수집기를 재시작합니다.
5. 거래소 앱 잔고와 대시보드 잔고를 직접 대조합니다.
6. 최소 일주일간 조회와 기록 누락 여부를 확인합니다.
7. 과거 데이터 백테스트와 모의운영을 완료합니다.
8. 주문 기능은 별도의 검토와 승인 후 연결합니다.

## 8. 자주 발생하는 상태

| 표시 | 의미 | 조치 |
| --- | --- | --- |
| `http_401` | 키 오류 또는 허용 IP 불일치 | 키를 채팅에 보내지 말고 거래소의 허용 IP를 확인합니다. |
| `disabled` | 사용자가 연결을 켜지 않음 | 인증 전에는 정상적인 안전 상태입니다. |
| `missing_credentials` | 활성화했지만 키가 없음 | `.env`를 장비에서 직접 확인합니다. |
| `collection_failed` | 네트워크·응답 처리 실패 | `next_data/logs`와 공개 API 사전점검을 확인합니다. |
| `실행 확인 안 됨` | 최근 heartbeat가 없음 | 과거 설정만으로 실행 중이라고 판단하지 않습니다. |

## 9. 안전 원칙

- API 키와 Telegram 토큰을 대시보드, 로그, 채팅, Git에 올리지 않습니다.
- Upbit, Binance, 국내주식 주문 워커는 각각 독립시킵니다.
- Windows와 Mac 또는 두 서버에서 같은 주문 워커를 동시에 실행하지 않습니다.
- 승률만 보고 전략을 선택하지 않습니다.
- 실제 주문 전에는 수수료, 슬리피지, 펀딩비와 최소 주문 단위를 검증합니다.
- 서버 이전 시 기존 워커 중지, 최종 원장 백업, 복원, 잔고 대조 순서를 지킵니다.

Mac 이전 절차는 `MAC_MIGRATION.md`를 함께 참고합니다.
