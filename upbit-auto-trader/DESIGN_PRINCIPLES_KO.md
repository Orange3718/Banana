# 설계 사상

## 1. 제품의 정체성

이 시스템은 비트코인 전용 봇이 아니라, 여러 거래소와 여러 자산을 같은 운영 화면에서 관리하는 암호화폐 자동매매 운영 시스템입니다.

Upbit 현물, Binance Futures 같은 계정은 화면과 공통 운영 규칙을 공유하지만, 인증 방식과 주문 규칙은 서로 다른 어댑터로 완전히 분리합니다.

## 2. 핵심 원칙

### 자산 중심

BTC를 고정 기준으로 삼지 않습니다. 거래소가 반환한 전체 보유자산을 원천 데이터로 사용하고, 각 코인별 수량, 현재가, 평가금액, KRW 환산액, 손익을 표시합니다.

### 설명 가능한 의사결정

추천이나 매매 신호는 결과만 보여주지 않습니다. 사용한 전략, 파라미터, 시장 국면, 신호 점수, 진입/청산 조건, 제외 사유를 함께 기록합니다.

### 관찰과 실행의 분리

시세 수집, 계좌 조회, 전략 계산, 알림, 주문 실행을 독립 모듈로 둡니다. 현재 기본 시스템은 읽기 전용이며, 주문 실행은 별도 권한과 위험 검증을 통과해야 연결합니다.

### 서버 이식성

운영체제에 종속되는 로직은 실행 스크립트에만 둡니다. 핵심 Python API, 저장 형식, 전략 계산, 로그 포맷은 Windows, macOS, Linux 서버에서 동일하게 동작하도록 구성합니다.

### 안전한 실패

인증 오류, API 지연, 데이터 누락, 가격 이상, 포지션 한도 초과 시 주문을 만들지 않고 `disabled`, `degraded`, `blocked` 상태로 남깁니다. 실패를 정상 상태처럼 표시하지 않습니다.

## 3. 논리 구조

```text
거래소 API
  -> Exchange Adapter
  -> Collector / Normalizer
  -> Store 및 이벤트 로그
  -> Portfolio / PnL 집계
  -> Strategy Lab / Signal Engine
  -> Risk Gate
  -> (향후 별도) Order Executor
  -> Telegram / Dashboard
```

대시보드는 저장된 공통 모델을 읽습니다. 거래소별 원본 응답을 화면마다 따로 해석하지 않으므로, BTC만 보이거나 KRW 환산 기준이 어긋나는 문제를 줄일 수 있습니다.

## 4. 계정 경계

각 계정은 `account` 식별자로 분리합니다.

- `upbit`: 현물, KRW 환산, 코인 잔고
- `binance_futures`: 선물 지갑, 포지션, 미실현 손익, 증거금
- `kr_stock`: 향후 국내 증권사 계좌용 독립 어댑터

공통화하는 것은 상태, 이벤트, 포트폴리오 표시, 알림 정책입니다. 주문 단위, 레버리지, 증거금, 호가 단위, 시장 시간은 계정별로 분리합니다.

## 5. 전략 운영 사상

짧은 주기를 목표로 하더라도 빠른 매매 자체를 성공 기준으로 삼지 않습니다. 수수료, 슬리피지, 체결 지연, 유동성, 최대낙폭을 포함한 순성과를 기준으로 비교합니다.

전략은 다음 순서로 동작해야 합니다.

1. 대상 코인과 데이터 품질을 확인합니다.
2. 시장 국면을 분류합니다.
3. 전략 신호와 예상 비용을 계산합니다.
4. 보유 한도, 일일 손실 한도, 코인별 금액을 검사합니다.
5. 신호의 사유와 파라미터를 기록합니다.
6. 실행 권한이 없으면 관찰/추천으로 끝냅니다.

과거 승률이 높다는 이유만으로 미래 수익을 보장한다고 해석하지 않습니다. 표본 수, 기간, 시장 국면, 수수료 반영 여부를 함께 표시합니다.

## 6. UI/UX 방향

첫 화면은 현재 운영 상태를 보여주는 관제 화면입니다. 왼쪽 메뉴로 기능을 분리하고, 상단에는 현재 계정, 실행 모드, 데이터 시각, 위험 상태를 고정 표시합니다.

색상은 상태 의미에만 사용합니다.

- 초록: 정상/수익/연결
- 노랑: 주의/지연/검토 필요
- 빨강: 오류/차단/손실 위험
- 파랑: 정보/분석

사이버펑크 시각 요소는 정보 계층을 방해하지 않는 범위에서 사용합니다. 숫자와 상태가 먼저 읽히고, 그래프는 자산 구성, 손익 추이, 신호 흐름을 비교하는 데 기여해야 합니다.

## 7. 알림 철학

텔레그램은 모든 로그를 복사하는 채널이 아니라 운영 의사결정 채널입니다.

- 장애와 주문 거부는 즉시
- 신호와 추천은 설정된 주기
- 정상 heartbeat는 낮은 빈도 요약
- 같은 이벤트는 일정 시간 억제
- 모든 알림에 계정, 코인, 시각, 현재 상태, 사유를 포함

## 8. 구현 순서

1. 읽기 전용 데이터 정확성
2. 자산/거래 이력/손익 대조
3. 전략 실험실과 재현 가능한 로그
4. 텔레그램 알림 정책
5. paper trading
6. 위험 게이트와 kill switch
7. 별도 주문 executor
8. 서버 배포와 운영 모니터링

계좌 데이터와 체결 이력이 틀리면 화면이나 자동화의 판단 근거가 무너지므로 이 순서를 유지합니다.
